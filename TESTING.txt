SMSYSTEM source and test guide

Layout
  apps/api/src       HTTP routes, business services, repositories; unit tests
                     stay next to their implementation as *.spec.ts.
  apps/api/tests     API route/contract tests with injected services and fake pools.
  apps/web/modules   Feature UI, helpers and their colocated tests.
  apps/web/shared    API clients, authorization, navigation and shared UI tests.
  packages/contracts Shared payload validation and status normalization tests.
  packages/permissions Shared permission and scope policy tests.

Commands (from repository root)
  Requirements: installed dependencies and Bun >= 1.4.0 for file isolation.
  npm ci
  npm test                 All web/API/shared tests.
  npm run test:unit        Colocated API, web and shared-package tests.
  npm run test:api         API route/contract suite in apps/api/tests.
  npm run typecheck       API and web TypeScript checks.
  npm run lint            Web ESLint checks.
  bun --no-env-file test --isolate ./path/to/file.spec.ts

The test commands disable automatic .env loading and isolate module mocks and
process globals per file. Do not load production environment files for tests.
Synthetic fixtures replace repositories, sessions, fetch and notification sinks.
The two connectivity tests are skipped unless RUN_CONNECTIVITY_TESTS=1 is set
explicitly; use only a disposable environment when running those probes.

Rules covered by the current regressions
  Job Plan: job-plan-runtime-read-model.spec.ts and job-plan-runtime.routes.test.ts
  keep the canonical runtime as the operational writer; historical SQL records
  remain readable. job-plan-draft-submit.spec.ts keeps drafts until a submission
  succeeds. job-plan-planner.spec.ts checks scheduling, daily targets and retries.

  Monitoring: monitoring.service.spec.ts, monitoring-scope.spec.ts and
  execution-history.spec.tsx check scope and worker execution history. Monitoring
  input does not start or stop the worker timer. Verification uses injected stores;
  it is not evidence of a production database write.

  QC: qc.repo.spec.ts and qc.service.spec.ts distinguish KD inspection from the
  final QA decision. Rework reuses the same Countdown and creates a Job Plan draft;
  only insufficient remaining time is extended. Repeated rejection is idempotent
  and a failed draft write rolls back the associated extension.

  RBAC: roles-access.spec.ts, roles-flow.spec.ts and rbac-policy.spec.ts require
  MIS plus user.manage for the role matrix. The reserved superadmin identity is
  tested separately in reserved-role.spec.ts. Module access and row actions still
  follow database permissions and session scope.

  Units/panels: unit-work-guard.spec.ts blocks new work for a held unit;
  units-parent.repo.spec.ts and master-panel-create-form.spec.ts cover child items
  using the existing parent relationship. Status contract tests accept supported
  casing variants without inventing completion or QC evidence.

Adding or changing tests
  Use a behavior name that explains the trigger and expected result. Put shared
  fixtures beside the suite that needs them. Prefer injected dependencies; keep
  database, Redis, HTTP, file writes and push delivery out of default unit tests.
  Test domain rules, rollback, retry identity and access boundaries. A SQL-string
  assertion verifies query construction, not execution against a real database.

Repository boundaries
  Markdown, prompts, assistant configuration, migration workspaces, SQL dumps,
  credentials, local diagnostics and build artifacts stay on the developer machine
  and are ignored by Git. Application SQL migrations already tracked remain source.
  package-lock.json supports Docker npm ci; bun.lock supports Bun development.
  Neither real phone/browser interaction nor production deployment is implied by
  a passing unit test suite.
